# 0001: v0.0.1の対象範囲を定義する

## 背景

Nioraは、登録済みの教科書から学習環境を起動し、実際に操作しながら学べる体験の提供を目指している。

最初のバージョンで教材投稿、利用者管理、認証・認可、複数種類の学習環境を実装すると、提供する機能が多くなる。まずは学習者が教科書を見て、対応する環境を起動・操作できる一連の体験を作る必要がある。

## 決定

v0.0.1では、次の機能を実装する。

- あらかじめ登録された教科書と章の一覧・内容表示
- 章に紐付いたWorkspaceDefinitionからUbuntuのWorkspaceを起動
- Workspaceへ接続するための短期ConnectionTokenの発行
- ConnectionTokenを使用したブラウザターミナルからのWorkspaceへの接続
- Workspaceの状態確認
- Workspaceの削除
- 期限切れになったWorkspaceの自動削除
- 起動・接続・削除に関する最低限のログ

v0.0.1では、次の機能を実装しない。

- アカウントと利用者の管理
- 外部認証サービスとの連携
- 利用者の役割や所有関係に基づく認可
- 教科書と章の投稿・編集・削除
- Ubuntu以外の学習環境
- HTTPサービスの外部公開
- データベースへの外部接続
- 学習環境の状態保存と再開
- 一般利用者への公開

v0.0.1は、ローカルまたはアクセスを制限した環境で利用する。

## 代替案

- 最初から教材投稿者向けの教科書管理機能を実装する
- 最初から外部認証と利用者単位の認可を実装する
- Ubuntu以外のOSや複数の環境テンプレートに対応する
- 一般公開に必要な機能をまとめて実装する

## 影響

- 教科書からUbuntu環境を起動して操作する最小の利用体験へ集中できる
- 登録する教科書、章、Ubuntu環境は開発・運用側で事前に用意する必要がある
- 教材投稿者によるWorkspace定義や、複数利用者での認証・認可は検証できない
- ConnectionTokenはWorkspaceへの接続権限として、安全な生成、有効期限、失効を実装する必要がある
- v0.0.1のまま一般利用者へ公開することはできない
